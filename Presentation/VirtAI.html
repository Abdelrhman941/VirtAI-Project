What is VirtAI?

VirtAI is a production-grade AI learning platform that transforms how students interact with educational content through an intelligent 3D avatar tutor.

  • Converse via voice or text with a lifelike 3D avatar instructor
  • Auto-generate quizzes, summaries, and diagrams from any document

Viseme System

  • Phoneme-to-Viseme — Text is converted to phonemes, each mapped to a viseme (mouth shape)
  • Blend Shape Weights — Each viseme sets specific morph target weights on the face mesh
  • Smooth Interpolation — Weights are lerped between visemes to avoid jarring transitions
  • Timing Sync — Viseme duration aligned with TTS audio timing for accurate lip-audio sync

Processing Details

  • Supported Formats — PDF, TXT, and other text-based document formats
  • Text Extraction — Library-based parsing that extracts raw text while preserving structure
  • Chunking Strategy — Fixed-size chunks with configurable overlap to prevent context loss at boundaries
  • Metadata Preservation — Each chunk stores its source document, page number, and chunk index

Storage Strategy

  • Chunk Table — Each chunk stored as a row in doc_chunks with vector embedding
  • pgvector Index — IVFFlat or HNSW index on embedding column for fast approximate nearest neighbor search
  • Document Status — Tracked via status field: uploading → processing → ready → error
  • Cleanup — Deleting a document cascades to remove all associated chunks and embeddings

Key Design Decisions

  • Three.js as Canvas Overlay — Avatar renders in a dedicated canvas, separate from DOM for GPU performance
  • WebSocket Hook — Custom React hook encapsulates connection lifecycle, reconnection, and message handling
  • Audio Pipeline — Web Audio API captures microphone input; AudioContext plays TTS streams
  • State Management — React Context + useReducer for chat state, avatar state, and UI state
  • Streaming Response — WebSocket messages are appended incrementally to the chat UI as they arrive

Dockerfile Strategy

  • Multi-stage builds — Minimize final image size by separating build and runtime stages
  • Backend — Python slim base → install deps → copy source → run Uvicorn
  • Frontend — Node build stage → Nginx serve stage for static files
  • Environment vars — Sensitive config via .env file, not hardcoded

Networking

  • Docker bridge network — All services communicate on an internal network
  • Port mapping — Only frontend (3000) and backend (8000) exposed to host
  • Volume mounts — Persistent data for PostgreSQL and uploaded files
  • Health checks — Docker healthcheck for each service ensures reliability

Technical Challenges & How We Solved Them

Five core engineering challenges encountered during development — and the concrete solutions shipped to production.

Real-Time Synchronization

Keeping avatar lip-sync, TTS audio, and streamed tokens perfectly aligned over WebSocket with minimal latency.

Event-Driven Pipeline

Unified event queue coordinates TTS audio chunks, text tokens, and viseme frames with timestamp-based alignment.

Lip Sync Accuracy

Mapping continuous audio to discrete viseme targets without robotic or mismatched mouth movement.

Smooth Interpolation

Lerp-based blend-shape transitions with configurable easing curves for natural lip movement.

RAG Relevance & Hallucination

Ensuring retrieved chunks are relevant and LLM stays grounded — no plausible-but-wrong answers.

Strict Prompt Grounding

System prompts force answers from context only; PGVector similarity threshold filters low-relevance chunks.

3D Performance in Browser

Holding 60 fps avatar render while WebSocket, audio worklet, and chat UI run on the same thread.

Optimized Rendering

Model decimation, texture compression, frustum culling, and isolated render loop priority from UI.

Intelligent Document Chunking

Splitting documents while preserving semantic coherence — no mid-sentence cuts that degrade retrieval.

Overlap Strategy

Configurable chunk overlap preserves context; chunk size tuned for embedding model's token window.
